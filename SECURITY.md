# SHADOWGRAPH — защита аккаунтов и проектов

Версия 4.3. Репозиторий содержит код, лицензии и страницу запуска. Учётных записей, рабочих проектов, ключей доступа и данных серверной базы в нём нет.

## Проверенные границы

- Ключ доступа имеет 256 случайных бит; в серверной базе сохраняется SHA-256 хеш. Ключ — самостоятельное удостоверение доступа, как пароль; дополнительного входа через ChatGPT нет. Зная ключ, можно войти в его профиль. Имя пользователя само по себе не является способом входа. Заголовки платформы и переданный клиентом ID аккаунта не предоставляют доступ.
- Ник уникален в базе: нормализация Unicode NFKC, регистр, распространённые похожие латинские/кириллические буквы, уникальный индекс. Служебные имена зарезервированы.
- Только роль владельца в серверной базе разрешает выпуск ключей участников. Переданный клиентом параметр role не даёт прав.
- Участник активирует отдельный ключ SGM со свободным ником. Повторное использование ключа для регистрации другого профиля запрещено; повторный вход по нему открывает первоначальный профиль. Партия содержит ровно десять разных ключей; повтор того же номера партии отклоняется. Сырые ключи показываются только в ответе на выпуск.
- Google и Telegram: Authorization Code + PKCE, одноразовое состояние с привязкой к HttpOnly-cookie, проверка RS256-подписи по фиксированному JWKS, issuer, audience, nonce, срока и времени выдачи токена. GitHub: PKCE, проверка состояния и получение устойчивого ID через официальный API с серверным токеном. Секреты приложений, коды и токены доступа не попадают в клиентский код. Полномочия запрашиваются только для базового профиля.
- Первая привязка внешнего сервиса требует правильного ключа существующего профиля или активации приглашения. Уникальная пара «провайдер + ID» не может быть переназначена другому профилю. Имя и почта не выбирают существующий аккаунт. Вход через ранее привязанный сервис выдаёт сессию только связанного профиля. Состояния и подтверждения привязки живут десять минут; просроченные не принимаются.
- Сессии: случайные токены, в базе только хеши, HttpOnly/Secure/SameSite=Strict cookie, срок семь дней. Новый вход меняет токен, Logout отзывает текущую сессию. POST проверяет Origin; вход и регистрация ограничены по частоте по хешу доверенного IP Cloudflare, с общей группой при отсутствии IP. Тело запроса ограничено при чтении потока. Только временная cookie возврата из OAuth имеет SameSite=Lax.
- Проекты, прикреплённые файлы и история в IndexedDB защищены AES-256-GCM. Отдельный случайный ключ хранилища для аккаунта сервер выдаёт только его авторизованной сессии; в localStorage/sessionStorage этот ключ не сохраняется. AAD связывает шифртекст с аккаунтом и ID проекта. Чужой ключ, изменение ID и повреждение шифртекста приводят к отказу расшифровки.
- Выход очищает ключ хранилища, объекты проектов, временные резервные копии и текст в интерфейсе. Новые вкладки обмениваются уведомлением о смене аккаунта и блокируют старое рабочее пространство.
- Старые открытые копии переносятся в зашифрованное хранилище. Старая база удаляется только после подтверждения записи каждого проекта в новом хранилище. При блокировке старой базы открытой вкладкой вход останавливается с просьбой закрыть старые вкладки. Более новые записи не заменяются старыми.

## Пределы защиты

Это проверка конкретных механизмов, а не сертификация и не обещание отсутствия любых уязвимостей. Хостинг и серверная база остаются доверенной частью системы. Доступ к разблокированной сессии пользователя, вредоносное расширение, скомпрометированное устройство или выполнение чужого JavaScript в контексте приложения находятся за пределами изоляции между обычными аккаунтами. Скачанные пользователем JSON, ZIP и PDF остаются обычными незашифрованными файлами — это намеренный экспорт.

Проекты локальные: вход на другом устройстве не синхронизирует их. Для переноса нужен экспорт и импорт. На GitHub Pages размещается только страница запуска; серверная авторизация и база работают на основном сервере.

В пустой новой серверной базе владелец не назначается первому посетителю. При обновлении подтверждённого приватного сайта существующий первый аккаунт становится владельцем. Для развёртывания с нуля владелец должен быть создан администратором хостинга до открытия регистрации.

## Проверка

Проверены самостоятельный вход и активация без ChatGPT, сохранение прежних ID аккаунтов и ключей хранилища, совместимость старых сессий, попытка повысить роль, чужой ID аккаунта, повторный ник и его варианты, повторная активация, повтор партии, Origin, ограничение размера запроса и частоты, logout и смена токена, отсутствие сырых ключей в базе, шифрование/AAD/подмена, очистка ключа после выхода и сохранение правок. Браузерная проверка подтвердила повторное открытие прежнего зашифрованного проекта, разделение владельца и участника и вход с очищенными cookie без ChatGPT. Тесты выполнялись с отдельными локальными данными.

OAuth проверен на тестовых ответах провайдеров и подписанных тестовых токенах: подмена подписи, алгоритма, audience, issuer, nonce, сроков, cookie, повтор callback, PKCE и попытка переназначения привязки. Полный вход на реальных сервисах требует зарегистрированных приложений и пока не проверен. При отсутствии настроек провайдер отключён.
